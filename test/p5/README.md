# Phase 5 等価性ハーネス

経路探索・時間系の保守的最適化（Phase 5, magi_CLAUDE.md「その8」）が**挙動を1ビットも変えていない**ことを機械照合するテスト。単一HTMLの `<script>` を抽出し、DOMスタブ＋決定的LCG上で実行する。

## 実行
```sh
test/p5/verify.sh                 # リポジトリ直下 index.html を Phase 5 直前(89ca12a)と照合
test/p5/verify.sh path/to.html    # 対象を指定
test/p5/verify.sh path/to.html <ref>  # 黄金基準のコミットを指定
```
Node 18+ 必要。`✅ PASS` なら経路探索の一手・全軌道・乱数消費が baseline と完全一致。

## 見た目の確認（`dev/screens.html`）
自動テストは「重なっていないか」までは縛れるが、**見やすいかどうか**は測れない。
そこは主要画面を並べて目で見る:

```sh
python3 -m http.server 8765     # リポジトリ直下で
```
→ <http://localhost:8765/dev/screens.html> を開く。全10画面（タイトル／メニュー／モード選択／
ハード設定／ショップ2タブ／設定／プレイ2種／リザルト）が並び、mobile / tablet / desktop を切り替えられる。

- **セーブデータは書き換わらない**。iframe は本物と同じ localStorage を見てしまうので、
  各フレームで `Storage.prototype.setItem` を潰してある（リザルトは保存処理を通るため必須）。
- `file://` では動かない（iframe の中を触れない）。必ずサーバー経由で開くこと。
- 本体側にデバッグ用の分岐は足していない。外から **function 宣言された関数**と DOM だけを触って各画面を出す。

## 構成
- `harness.js` — DOMスタブ・LCG・時計制御。`node harness.js <html> <mode> [seed]`。mode = `path|sim|pause|perf`。
- `epilogue_path.js` — 経路探索オラクル。40マップ×全開始セル×掘削2ラウンドの一手をハッシュ化（保存則1の中核）。
- `epilogue_sim.js` — 手組みシナリオを1000tick駆動し全エンティティ(x,y,hp,cd)＋乱数消費回数をハッシュ化（統合レベル）。
- `epilogue_pause.js` — P5-6 ポーズ修正の正当性（ポーズ中 gameTime 凍結）。
- `epilogue_perf.js` — 深度25 vs 250 の経路探索コスト比（深度非依存の実測）。
- `epilogue_trade.js` — **Phase 3 取引コード（道A）の単体検証**。`node harness.js ../../index.html trade` で52項目。形式/チェックサム/ホワイトリスト/二重受領/所持上限/traded隔離/UI経路スモーク。`failed: 0` を維持すること。
- `epilogue_camera.js` — **ミニマップ（一定縮尺）と勇者追尾カメラの検証**（`... camera`）。22項目。表示範囲の固定とクランプ／追尾対象の選び方／追従の収束と端クランプ／スクロールバー非表示のCSS。
- `epilogue_forge.js` — **宝具のレベル・鍛錬・昇格の検証**（`... forge`）。49項目。Lv補正の値／ランク別上限／経験値設計（全ランクで同ランク10個＝Lv MAX）／鍛錬の拒否条件／昇格の条件・継承・**消費はLv昇順**／UI経路スモーク。`table` に各ランクの必要経験値が出る。
- `epilogue_kind.js` — **宝具の系統（アーキタイプ）の検証と出現率の実測**（`... kind`）。18項目。アイコンと名前のペア整合／系統別の効果出現率／進化の同系統優先／旧セーブ救済。`measured` に系統別の実測%が出るのでバランス調整に使える。
- `epilogue_design.js` — **Phase 4 デザイン強化＋UIの土台の検証**（`... design`）。53項目。
  後半（7〜11）が **UIの土台を縛る部分**で、ここが赤い＝「その場しのぎの直し方をした」合図:
  - **7. プレイ画面の配置契約** — HUD は `#gameCenter` の名前付きグリッドのセルに入る。`position:absolute` で浮かせない。
  - **8. 盤面と電光掲示板** — 列数は奇数（入口が中央＝左右対称）／お知らせは掲示板を右から左へ流れる。
  - **9. 画面の配置契約** — 全画面が `head / body / foot` の3段。伸びるのは中身の段だけで、内側にスクロールする。
    **はみ出しは構造で起きない**ので、`adjustResultScale()` のような「後から縮める」補正を足してはいけない（9f が検出する）。
  - **10. デザイントークン** — トークンと同値の色を直書きしない。直書きするとサポーターテーマ（`:root` を差し替える）が
    **その箇所にだけ効かず、テーマが半端に壊れる**。余白は 2px 刻みの目盛りに乗せる。
  - **11. 見た目確認ページ** — `dev/screens.html` が呼ぶ名前と id が本体に在ること。
    ゲームの状態変数は `let/const` 宣言で **window のプロパティではない**ため、外から触れるのは
    `function` 宣言された関数と DOM だけ。本体の関数名を変えると確認ページだけ黙って壊れるのを防ぐ。

  - **1〜6（Phase 4 デザイン強化）** — タイルプリレンダが起動時1回かつ乱数非消費／深度トーンの単調性と上限／描画ループにグラデ・パターン・`shadowBlur` が無いこと（性能予算 D-2/D-3）／外部リソースなし（D-1）／全レア度のクラスとバッジ（D-4）／描画とリザルト演出で例外なし。**canvas描画やCSSを足したらここを緑に保つ。**

- `epilogue_affix.js` — **アフィックス（基礎/倍率/射程/索敵）と effStat・遠隔攻撃**（`... affix`）。`dynamicEquip` は**ラン中の装備変更が即反映されること**（以降に湧く個体＋場にいる個体、HPは割合維持、`startGold` はラン中に効かない）、`dynamicLevel` は**レベルアップの即反映**（ちびは成体の半分・満タンは満タンのまま）。強化まわりを触ったらここを緑に保つ。
- `epilogue_balance.js` — **戦闘バランスのものさし**（`... balance`）。行動レート・DPS・必要体数 c*・拮抗時の決着時間を解析式で算出。数値をいじったらまずここを見る。
- `epilogue_economy.js` — **経済のものさし**（`... economy`）。収入（モード×深度）・Lv上げの所要時間・ダイヤの需給・戦力天井（Lv上限別に何波で破綻するか）・宝具の供給と鍛冶コストを一覧化。通貨まわりの数値をいじったらここを見る。
- `epilogue_colosseum.js` — **コロシアムモードの検証と目盛り**（`... colosseum`）。69項目。盤面（21×21・内側は全部壁361マス・門は4マスだけ）／**城の配置と「開通した門＝攻め口」**（掘って繋げた門からのみ勇者が来る）／**指令**（種別ごとの集合地点・未設定はランダムウォーク・fertileは城優先）／wave構成（体数・門・勇者の強さが富に連動しないこと・ボスは1体）／経済（討伐 15+wave・修復・早出し）／精算（ゴールドは銀行に入らない・💎は記録更新の差分のみ・実レベルを保存しない）／兵站（fertile率・繁殖の専用枠・勇者の出現がfertileを再供給）／**他モードを壊していないこと**。後半に wave別の物量と「実際に何wave耐えられるか」の実走が出るので、コロシアムの数値をいじったらここを見る。
- `epilogue_crowd.js` — **同一マスの同居数とサブセル配置の実測**（`... crowd`）。ゲームロジックに「1マス1体」の排他は無く、モンスターも勇者も同じマスに何体でも入る。従来は描画がマス中心固定だったため、戦闘中は **7〜9割の個体が完全に重なって見えていなかった**。現行は1マスを 2×2 に分け、**個体の大きさは同居数によらず原寸のまま**上限4体を並べる。見るべき値:
  - `hiddenPctBefore → hiddenPctAfter` — 見えていなかった割合の改善量。探索中（勇者なし）はほぼ0%になる。
  - `fitAtWorstGap` — 最悪の席間隔に対して各種が原寸で収まるか。**スライム/ゴブリン/ゴーレムは収まり、レイスと勇者だけ食い込む**（本体が席間隔15pxより大きいため。大型なので「重なって群れている」として読ませる）。ここが赤くなる＝キャラの造形を大きくしすぎた合図。
  - `heroHiddenBad` — **席が足りているのに隠れた勇者の数。常に0であること。** 席順は「勇者が先、あとは eid 昇順」で、これを eid だけにすると先に生まれたモンスターが席を独占して勇者が画面から消える。
  - `bench` — `assignSubcells` の1フレームあたりコスト（100体で 0.01ms 台＝60fps予算の0.1%未満）。

  1マスの見せ方や表示上限 `SUBCELL_MAX` を触ったらここを見る。`CROWD_DUMP=1` を付けると実フレームの描画座標を JSON で吐く（目視確認用）。
- `epilogue_tempo.js` — **テンポの実測**（`... tempo`）。実際に gameLoop を回して「進入→接触→決着」の秒数を測る。解析式では見えない経路探索・射程・複数体の割り込み込みの実値。
- `epilogue_license.js` — **課金ライセンス（MD1 トークン）の検証**（`... license`）。65項目。実鍵ペアをその場で生成して `LICENSE_PUBKEYS` に注入するので、Stripe も Cloudflare も鍵ファイルも要らない。改ざん検知／ドメイン分離／未知ビットの無視／失効／鍵ローテーション／永続化／UI 経路／**出荷物の静的検査**（テスト用 kid が混入していないか・localStorage キーの接頭辞・最初の `<script>` がゲーム本体であること）。課金まわりと base64url ヘルパを触ったらここを緑に保つ。

## 黄金基準ハッシュ
- **path: `bf386fb2`（18844サンプル）— 現行（`BASE_COLS = 19`）の基準**。
  サンプル数は盤面の広さで決まるので、**列数を変えると必ず変わる**。変わったときは
  「経路探索を壊したのか、盤面を変えただけなのか」を次の手順で切り分けること:

  ```sh
  # BASE_COLS を 20 に戻したコピーを作って path を取る
  sed 's/const BASE_COLS = 19;/const BASE_COLS = 20;/' index.html > /tmp/cols20.html
  node test/p5/harness.js /tmp/cols20.html path
  ```

  ここで **`a72aec6f`（19926サンプル）** が出れば経路探索のロジックは無傷。
  この `a72aec6f` は Phase 5 以降ずっと不変の値で、**経路探索を壊していないことの証明**として使う。
  （2026-08-09 に盤面を 20 列 → 19 列（左9＋入口1＋右9）へ変更。入口が中央に来る＝左右対称に
  するため列数は奇数を保つこと。この変更で path の基準値だけが移り、上の手順で旧基準との一致を確認済み）
- sim : バランスを変えると当然変わる。直近の基準は **`10dd6d78` / rngCount 462**（2026-07-27 バランス調整後）。
  `verify.sh` の既定基準は `HEAD` なので、普段は「作業ツリーが直前コミットから挙動を変えていないか」を見る形になる。
